# 🎮 Video2Team 设计文档

> **Video2Team — 把大佬的作业，改成你抄得动的作业**
>
> B站明日方舟挂机攻略视频 → AI 提取阵容 → 结合弹幕/评论区实战替代建议 + 我的干员 box → 输出一份我当前 box 能用的阵容。

---

## 1. 背景与动机

明日方舟活动关卡的经典场景：

1. 找到一挂机攻略视频，发现阵容里有干员自己没有；
2. 弹幕/评论区散落着「XX 可以用 YY 代替」的实战建议，但混在几百条无关发言里；
3. 只能一个个记下来、逐个核对自己有没有、再判断能不能用——非常累。

本项目的目标：**把这三步压缩成一次输入**。用户丢一个攻略视频（或合集）链接 + 自己的干员练度，程序输出一份「你当前 box 可用的挂机阵容」，并标注每个替换位的来源和风险。

## 2. 与 Video2Shop 的关系：同一范式的领域迁移

Video2Shop 的核心范式是三段式：**视频 → 清单 → 对比持有 → 补齐方案**。本项目完全套用，仅替换领域对象：

| | Video2Shop | Video2Team |
|---|---|---|
| 视频类型 | 美食/手工 | 活动关挂机攻略 |
| 清单 | 配方（食材+工具） | 阵容（干员+技能+部署顺序） |
| 我的持有 | 厨房已有物品 | 干员 box |
| 缺口处理 | 京东加购购买 | 替补干员填坑 |
| 增量信息源 | — | **弹幕/评论区实战替代建议（众包）** |

Video2Shop 约 60-70% 代码可直接复用（下载、抽帧 OCR、DeepSeek 双模式、GUI/Web 骨架、preflight）。

## 3. 核心设计决策（已收敛）

### 3.1 分析单元 = 关卡（三种合集形态，侦察后修订）

B站攻略合集实测存在三种形态（验证样本与细节见 [notes/recon.md](notes/recon.md)）：

| 形态 | 弹幕 | 评论 | 路由方案 |
|------|------|------|---------|
| a. 独立视频系列（一关一视频） | 天然隔离 | 天然隔离 | 无需路由 |
| **b. 多分P单一视频（实测常见）** | **按分P cid 天然隔离** | 全合集混在一个评论区 | 分P标题（`view.pages[].part`，写明关卡名）正则路由 |
| c. 长视频不分P | 混杂 | 混杂 | 弹幕时间戳 + AI 识别关卡切换（v2 兜底） |

因此分析单元定义为「**关卡**」：

- 独立视频 = 视频即关卡，弹幕/评论无需任何路由；
- 多分P视频 = 分P即关卡，弹幕天然按 cid 隔离，评论按分P标题正则路由；
- 用户输入合集时，遍历每个关卡独立跑管道，最后按关卡汇总。

### 3.2 box 数据源：v1 用 Excel，v2 上森空岛扫码

明日方舟无官方第三方查询 API，分两版走：

| 版本 | 方式 | 说明 |
|------|------|------|
| **v1** | **一图流导出的 Excel** | 用户在 [ark.yituliu.cn](https://ark.yituliu.cn/survey/operators)「我的干员 → 导出为 Excel」，程序解析练度表。零授权、零风险、开发量最小。**格式已实测确认**（2026-09：单表 431 行 × 14 列，含未招募干员图鉴，必须按「是否已招募」列过滤，详见 notes/recon.md；解析器已实现于 `src/shared/box.ts`） |
| **v2** | **森空岛扫码登录** | 程序展示二维码 → 用户森空岛 App 扫码 → 自动获取 cred 凭证 → 签名调 API 拉干员数据。协议已由开源社区完全逆向（[Skland_API](https://github.com/ProbiusOfficial/Skland_API)），一图流/riic.autos 均已跑通，照抄体验即可 |

备注：

- 森空岛 API 是社区逆向接口（cred + token 签名），鹰角历史上限制过第三方拉取，签名算法可能随版本变动需跟随社区维护 → **Excel 导入永远保留作为兜底**；
- 凭证安全承诺：cred 仅内存使用、不落盘（或显式加密存储并告知用户）；
- ~~截图 OCR 识别 box~~：已砍掉，有 Excel 和扫码两条更优路径。

### 3.3 替代知识体系：三层结构

「这个角色能代替那个角色」的知识在生态里有三种载体，粒度和来源完全不同：

| 层 | 载体 | 粒度 | 说明 |
|----|------|------|------|
| **L1 干员字典+属性** | PRTS/一图流开源数据 JSON | 无替代关系，仅名字/属性 | 只做校验（防幻觉）和 LLM 上下文，**永不参与推荐**。配套**纠错集**（`data/aliases.json`：昵称/黑话 → 全名对照），与 LLM 还原、字典校验构成三层防线：① 别名表预替换/注入 prompt → ② LLM 还原为全名 → ③ 字典校验拦截还原错误；校验失败的称呼自动记入 `corrections_pending.json`，人工确认后并入别名表（动态积累） |
| **L2 泛化替代知识** | **UP主制作的替换分析图表**（轮换池简评/干员简评类视频中的「挂机替换概率/问题」表格） | 条件式：「非极端高压、法伤真伤环境可考虑替换」+ 风险说明 | UP 主实战经验人工整理，生态中**唯一现成的结构化替代知识**，通过抽帧 → 多模态提取入库 |
| **L3 实战验证记录** | 弹幕/评论「XX换YY能过」 | 关卡绑定：「这关这样换」 | 弹幕/评论挖掘，高赞加权 |

兜底：LLM 结合关卡机制 + 属性上下文推断。属性相似度匹配：不做（理论相似 ≠ 实战能过）。

**查询顺序：L3 > L2 > LLM 推断**——先看本关有没有人亲测过，再看条件式泛化知识是否匹配本关环境，最后才让 LLM 猜。

补充设计要点：

- **L2 数据源是另一种视频**：替换分析表格不在挂机攻略视频里，而在轮换池简评/干员简评类视频中。两种视频类型都进数据源。
- **替换是多粒度的**：L2 图表底部的语义注解（如「替换指的是攻奶不换，部署位置不换。实在没有，可换攻速或换位置算换操作」）表明替代类型至少有：换干员 / 换技能或攻速 / 换部署位置 / 该格改手动操作。提取 L2/L3 时保留类型标注，推荐输出同样带类型。
- **L2 的条件匹配依赖关卡环境信息**（高压/法伤/物伤/真伤等），来源：攻略视频解说/简介、PRTS 关卡数据。v1 实现；v0 泛化知识仅展示给用户参考，不自动套用。
- **积累策略**：冷启动靠手动提取知名 UP 的简评视频图表；运行时每次分析视频，抽帧检测到图表即提取入库（v2 考虑共享库）。

### 3.4 关键位 vs 工具位

挂机攻略里通常只有 1-2 个关键干员动不得，其余是灵活工具人。推荐引擎先让 AI 从解说/简介/置顶评论中标记**关键位**，替换策略分级：

- 有关键位的替换 → 高风险标注，提示「建议回评论区验证」；
- 工具位替换 → 常规标注。

推荐错了玩家会真实翻车，容错要求远高于「买错一瓶酱油」，所以**每个替换位必须带来源与风险等级**。

### 3.5 产品形态与技术栈（已拍板：浏览器插件）

**形态：浏览器插件（Chrome Manifest V3 + TypeScript + Vite 构建）。**

选择依据：v0 管道全是轻请求（简介/置顶评论、弹幕/评论 API、Excel 解析、LLM 调用），无重计算，插件装得下；入口体验最好（看视频时点一下）；B站请求携带用户登录态，风控最友好；低频工具适合「装完躺着」的形态。

| 项 | 决策 |
|----|------|
| 运行时 | Chrome MV3（Edge 兼容） |
| 语言/构建 | TypeScript + Vite（+ @crxjs/vite-plugin 或手写 manifest） |
| 入口 | **视频页浮动入口**（右缘 hover 唤起按钮 + 页内面板：抓帧/粘贴/分析/结果，content script shadow DOM）+ popup 面板（工具栏图标，状态恢复用）。截图与任务状态经 storage.session 两入口互通 |
| 配置 | `chrome.storage` + options 设置页（API key、box 管理），**不再使用 YAML 配置文件** |
| Excel 解析 | SheetJS（xlsx）纯前端解析，用户本地选择文件，不上传 |
| 分发 | Edge 商店（国内可直接访问）+ crx 手动安装双通道 |
| 依赖的服务 | B站公开 API（用户身份）+ **任意 OpenAI 兼容 LLM 接口**（用户自配：预设 DeepSeek/硅基流动/智谱/Kimi/通义/豆包/OpenAI/OpenRouter/本地 Ollama + 自定义端点，Key 存 chrome.storage） |

**本地分析服务（远期可选项）**：仅服务于「全自动批量」场景（视频下载+抽帧）；主流程完全不依赖它——阵容来源是用户提供的画面（抓帧/粘贴）。重活永远是可选，不绑架形态。

**复用策略变化**：Video2Shop 的 Python 代码复用率趋近于零（v0 用不上抽帧 OCR），真正复用的是流程设计、prompt 设计与接口知识。

### 4.1 阵容提取路径实测修订（2026-09-13，端到端验收后）

**实测问题**：BV18bYL65E54 验收中，简介列出的是全合集「常用干员」（40+ 人），并非 SR-EX-8 的通关部署——基于它产出的适配结果对本关基本无用（保留/无解名单与实战阵容脱节）。

**真阵容的两种视频帧载体**（用户实证截图）：

1. **编队页帧**：「快捷编队 / 开始行动」UI，干员卡片网格（头像 + 名字 + 等级 + 模组），含「助战干员」位；
2. **开局摆放帧**：画面大字关卡名（如「SR-EX-8 虚无之顶」）+ 敌方计数 + 底部**部署顺序字幕**（「①遥↓②图亚↑③德→④安←⑤纶←⑥雪⑦理↑⑧泰⑨熊↑」）+ 干员头像费用条。

**修订（v0.5，用户方案采纳）**：阵容来源 = **用户提供的画面**，三通道：

1. **抓取当前画面（首选）**：用户暂停在编队页 → 点插件「抓取当前画面」→ content script 用 canvas 抓取 `<video>` 当前帧（B站播放器为 MSE blob 流，同源可绘制）→ dataURL → DeepSeek 多模态提取；
2. **Ctrl+V 粘贴截图**：canvas 抓取失败/想用外部截图时的保底，popup 监听 paste 事件取剪贴板图片；
3. **文件选择**：截图文件导入。

要点：

- 编队页是静态画面，**一帧足够**，无需视频下载/抽帧——本地分析服务降级为**远期可选项**（仅全自动批量场景需要）；
- 开局摆放帧（部署顺序字幕）**暂时跳过**——并非所有攻略视频都有该字幕，后续作为可选增强；
- 「大模型直接处理视频/视频链接」不可行：LLM API 无法访问B站需登录态的 DASH 分段流；抓帧转图是等价且便宜的做法；
- **文本路径不再产出结果集**：简介/置顶评论降级为截图提取时的辅助上下文（帮助 LLM 识别技能/专精说明），用户未提供画面时 popup 直接引导抓帧/粘贴，不展示无用的适配结果；
- 干员名单含「助战干员」位（好友干员，不在用户 box），标记 support 供推荐层区分。

## 5. 数据模型（核心结构）

定义见 `src/shared/types.ts`，此处为设计总览：

```
Roster（阵容）                    —— ① 的输出
 ├─ stage: str                    关卡名，如 "EX-8"
 ├─ video_id: str                 来源视频 BV 号
 ├─ slots: list[RosterSlot]
 │   ├─ operator / skill / mastery / deploy_order
 │   └─ is_key / key_reason       关键位标记及依据
 └─ source: description | pinned_comment | ocr_llm

Substitution（实战替代映射，L3）   —— ②a 的输出
 ├─ removed / replacement         谁被谁替
 ├─ kind                          替换类型：operator_swap | skill_swap
 │                                  | position_swap | manual
 ├─ stage                         所属关卡
 ├─ evidence                      弹幕/评论原文引用
 ├─ source: danmaku | comment | pinned
 ├─ likes                         热度，可信度权重
 └─ verified                      干员名字典校验通过

GenericSubstitution（泛化替代知识，L2） —— ②b 的输出
 ├─ removed / replacement         谁可被谁替（replacement 可为空，
 │                                  表示「可被同类干员替」）
 ├─ kind                          替换类型（同上）
 ├─ conditions                    可替换的情况（环境条件）
 ├─ risks                         可能出现的问题
 ├─ semantics                     语义注解（如「攻奶不换，部署位置不换」）
 ├─ source_video                  来源视频
 └─ origin: chart | narration     提取自图表帧 / 解说词

Box（干员 box）                   —— 用户输入
 ├─ operators: dict[name → OperatorEntry(name/elite/level/masteries)]
 └─ source: excel | skland

RecommendedSlot（推荐结果）       —— ③ 的输出
 ├─ original                      原阵容槽位
 ├─ final_operator / status: keep | substituted | unresolved
 ├─ kind                          替换类型（同 Substitution.kind）
 ├─ via: Substitution | GenericSubstitution | None   采用的知识条目
 ├─ risk: low | medium | high     关键位替换 → high
 └─ evidence_url                  评论区溯源链接
```

## 8. 路线图（2026-09-16 二次校准 —— 按「老玩家 + 核心价值」裁剪）

> **产品定位收紧：一个「分析弹幕/评论 → 给出可执行建议」的工具——只做搬运与校验，不做发明。**
> 对中后期玩家（box 接近齐全），核心价值 = 阵容识别自动化 + 社区建议的有效整理；
> box 适配（红绿/替换）主要服务新手与中登玩家——保留为招牌能力，但不围绕它追加投入。

### 🚫 明确不做（及原因，防止重复讨论）
- **无建议时的 LLM 兜底推断**：与「只搬运社区实战证据」的定位冲突，发明建议会稀释可信度

- **长视频分段路由**：单关视频与多分P形态已覆盖绝大多数攻略，收益低
- **L2 泛化替代知识（表格截图提取）**：改为按需触发（遇到值得沉淀的替换表格再临时提取），不进路线图
- **共享知识库 / 干员数据自动更新 / 本地分析服务**：超出当前阶段，暂缓

## 9. 风险与对策

| 风险 | 对策 |
|------|------|
| 替代推荐翻车（核心位被乱替） | 关键位分级 + 风险标注 + 引导回评论区验证 |
| 森空岛逆向接口被官方限制/签名变更 | Excel 导入永久保留为兜底；跟随 Skland_API 社区更新 |
| LLM 幻觉不存在的干员名 | 所有提取结果过干员名字典校验 |
| 弹幕噪音大、有效建议稀疏 | 正则粗筛 + LLM 精筛；评论区（尤其高赞）权重高于弹幕 |
| 评论使用昵称/黑话缩写（实测「ew+玛恩纳+余」） | LLM 提取时同时还原为干员全名，再过字典校验拦截还原错误 |
| 攻略视频画面不含完整编队信息 | 引导补抓助战详情页等多张图；识别不到时明确报错而非猜测 |
| 攻略时效性（旧版本关卡） | 输出时标注视频发布时间与游戏版本（若有） |
